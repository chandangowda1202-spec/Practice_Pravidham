# 🤝 Team Rules — Practice_Pravidham

These rules keep the repository clean, respectful, and useful for everyone long-term.

---

## 📂 1. Work Only Inside Your Own Folder
Each member commits **only** to their own named folder (`Chandan/`, `Pavan/`, `Kanhaiya/`, `Shreya/`, `Aishwarya/`). Do not create or edit files outside your folder (except shared `Resources/` additions, agreed upon by the team).

## ✍️ 2. Use Meaningful Commit Messages
Bad: `update`, `fix`, `asdf`
Good: `Pavan: Solved Binary Search (LeetCode) using two-pointer approach`

## 🔄 3. Pull Before You Push
Always run `git pull origin main` before starting work to avoid conflicts and outdated code.

## 🚫 4. Never Upload Executable/Build Files
Do not commit `*.exe`, `*.o`, `*.obj`, or other compiled/temporary files. These are already excluded by `.gitignore`, but double-check before committing.

## 🏷️ 5. Keep Filenames Descriptive
Name files after the problem, not generic terms:
```
✅ two-sum.cpp
✅ 1523A-count-doubles.cpp
❌ sol.cpp
❌ new1.cpp
```

## 🙏 6. Respect Other Members' Code
Never edit, delete, or "improve" another member's solutions without asking. This is an individual practice archive, not a shared codebase.

## 📅 7. Be Consistent
Aim to commit regularly (daily or a few times a week) — consistency builds a strong GitHub contribution graph and real skill.

## 💬 8. Communicate Changes to Shared Files
If you want to add or edit something in `Resources/` or the root `README.md`, mention it to the team first to avoid overwriting others' work.

## 🧹 9. Keep Folders Organized
Use platform subfolders inside your own folder:
```
Chandan/
├── LeetCode/
├── Codeforces/
├── CodeChef/
└── Other/
```

## 🌟 10. Have Fun & Keep Learning
The goal is growth — celebrate each other's progress and don't hesitate to ask for help.

---

| Rule | Why It Matters |
|---|---|
